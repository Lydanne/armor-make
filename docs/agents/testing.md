# 测试约定

## 默认观察接口

当前需求已经明确目录查找、命令转发和显式安装/卸载这些行为。优先通过以下接口验证，而不是为每个内部函数增加镜像测试：

| 接口 | 观察内容 | 不证明的内容 |
| --- | --- | --- |
| armor-make inspect | 实际操作目录、配置来源、搜索顺序、诊断不泄密 | 远端认证或写权限 |
| armor-make run / 已安装入口 → 替身原始命令 | 参数、选定环境、stdout/stderr、退出状态 | 官方程序所有特殊语法 |
| install / uninstall → 临时目录 | 入口归属、重复安装、既有文件保护、清理 | 真实用户目录已安装 |
| 官方 Git → 临时仓库 | 原生配置定向、local 优先级和路径解释 | GitHub/Gitea 推送身份 |
| 官方 tea → 临时登录配置 | 本机版本的离线配置读取 | API 凭证有效性 |

任务已经指明其中接口及场景时沿用该范围；新增或改变接口、扩大测试面时先写清拟验证的行为和范围，缺少必要需求时再确认。不要为资料初始化发起业务测试。

## 反馈循环

缺陷先给出捕获用户症状的命令或测试，并观察它失败；一次修改一个假设，再运行同一信号。功能按可交付的一小段行为完成 red → green → refactor。

使用临时目录、虚构配置和替身命令，保留真实原始命令的少量离线集成测试。真实 tea 不存在时相应测试可能跳过，报告结果要区分通过和跳过。

针对参数解析使用官方 CLI 合同及具体样例，不从实现生成预期值。不能把配置路径、提交署名或公共仓库读取成功当作账号证明。

当前适用命令由 package.json 定义：代码变更运行 check、test；AI 资料运行 check:ai；发布文件变更核对 pack 预览。只在新变化、失败或未解决疑点需要时扩大验证。
